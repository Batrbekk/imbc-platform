## Finding Stage6-N1 / P2 — reproduced, then closed

`operator-notes.expand.sql:72` and `:81` define author/operator-organization and operation-actor/operator-organization composite FKs into the **current** user_accounts organization. After a valid note create, changing the author's account from operator organization A to B fails PostgreSQL23503, constraint operator_note_author_scope_fk. The second operation FK imposes the same restriction independently. Canonical DBML retains author identity and the note's operator organization separately; no permanent account-organization rule was found or claimed by the owner. This new history table should not silently impose that rule.

Use stable author/actor ID FKs, preserve historical note/operator-organization values, and retain current actor/organization equality checks and locks in the API/native seal. After reassignment, stale A authentication must fail; refreshed B authentication must not expose/delete the old A note; A colleagues and permitted IMBC staff must retain its exact body, origin and history. The actual probe is a privileged native account update on the isolated database, not a claim that the current admin UI offers an organization-transfer route.
