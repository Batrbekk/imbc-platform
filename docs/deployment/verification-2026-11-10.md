Compose, Caddy и deployment-скрипты проверены; миграции завершились успешно. После добавления тестового администратора API-набор расширен до 56 тестов, включая 20 интеграционных; результаты повторной проверки приведены в последнем разделе.

## Проверки на сервере

- HTTPS с действующим сертификатом, готовность сервисов, закрытые порты данных и защищённый Mailpit.
- OIDC Code + PKCE, защищённые cookies, почтовый OTP, ответственность, каталог и дашборд.
- Регистрация тестового производителя, очередь приглашения, подтверждение email, имя/фамилия и установка пароля, стартовая страница производителя.
- Ссылки приглашения и сброса на 72 часа; восстановление из другого браузерного сеанса с новым входом BFF. Старый пароль отклоняется, новый работает.
- Пауза отправки OTP, запрет повторного использования кода и изменяющих запросов без Origin/Referer.
- Реальный worker отзывает прежние сеансы и доверенные устройства после смены пароля; новое устройство снова требует код.
- Выход BFF завершает сеанс Keycloak и возвращает локальную страницу без токенов в URL. Реальный подписанный backchannel logout отзывает сеанс и сохраняет запрет повторного использования sid.
- Публичный backchannel endpoint отвечает 404, включая конечный слеш, изменение регистра и query string. Внутренние уведомления Keycloak проходят проверку подписи.
- В браузере проверены формы входа, восстановления и регистрации на shadcn/ui, смена языка и отсутствие ошибок консоли. Матрица экранов темы отдельно проверена в мобильном и широком представлениях.
- Realm sync сохраняет дополнительные атрибуты клиента, пользователей и секреты. Directory mount и reload Caddy применяют заменённые при загрузке конфигурационные файлы.

Временные аккаунты этих автоматических сценариев, профили, identities, sessions и письма удалены; оставшихся временных аккаунтов — 0. Неизменяемый аудит сохранён. Отдельная тестовая БД и её временные реквизиты удалены; данные работающего стенда сохранены. Постоянные seed-аккаунты и отдельно созданный позднее тестовый администратор сохранены для ручного тестирования.

## Открытая проблема: предупреждение Chrome на iPhone

После заполнения имени и фамилии пользователь получил предупреждение «Опасный сайт». По событиям сервера email подтверждён, имя/фамилия и пароль сохранены; затем iPhone получил переход с `/api/auth/login` к форме идентификации, но callback первого входа не завершился. На этом этапе личный аккаунт ещё не прошёл MFA и принятие ответственности. Позже пользователь успешно прошёл свежий вход и почтовый код и открыл `/account` в браузере Codex. Предыдущая попытка в оставленной вкладке истекла: callback пришёл через 31 минуту при сроке попытки 10 минут; кнопка повторного входа запустила исправный новый поток.

Проверены действительный TLS-сертификат на точное имя, происхождение ссылок письма и форм, совпадение опубликованного JS со сборкой, набор контейнеров и изменения файлов. Неожиданных внешних ресурсов, перенаправлений или подмены в этих проверках не обнаружено. Это ограниченная проверка, которая не доказывает ложное срабатывание защиты браузера. Публичный Google Transparency Report не дал однозначного вердикта.

С разрешения пользователя 10 ноября 2026 года отправлено обращение через официальную форму Google Safe Browsing; интерфейс подтвердил «Отправлено». В него включены только URL входа без одноразовых параметров и описание выполненных проверок. Подтверждения снятия предупреждения пока нет; отправка обращения не означает, что классификация уже изменена. Предупреждение не обходилось, защита браузера не отключалась. На момент отправки обращения NSG ограничивал HTTPS IP разработчика. Позже по запросу владельца HTTPS открыт для Internet; служебные страницы сохранили IP-ограничение.

## Публичный доступ и тестовый администратор

По запросу владельца HTTPS/443 открыт в NSG для Internet. SSH остаётся ограниченным IP разработчика. Caddy до публикации проверен с недоверенного Docker-адреса: Mailpit, Keycloak admin/master и варианты их путей недоступны, поддельные forwarding-заголовки не дают доступа. Сервисы данных продолжают слушать только внутреннюю сеть/loopback.

Создан отдельный `test-admin@imbc.local` с обязательным случайным паролем и фиксированным OTP `000000`, ограниченным immutable UUID, ролью administrator и явно включённым development-tier. Код требует выпуска, срока действия и допуска по числу попыток, повторное использование запрещено; письма для тестового кода не отправляются. В живой проверке пройдены OIDC/пароль, OTP, ответственность, `/account`, запрет каталога и полный выход. Обычный оператор отдельно прошёл вход со случайным почтовым OTP. Личный аккаунт владельца не использовался в тестах.

После изменений прошли 56 тестов API, включая 20 интеграционных PostgreSQL 18, web typecheck/ESLint и 4 web-теста, production-сборки API/web. Безопасные значения конфигурации по умолчанию и выключение фиксированных кодов после смены scope проверены отдельными тестами.

## Короткий адрес формы входа

Тема IMBC заменяет видимый адрес обычной формы входа на `/login` после загрузки. Изменение ограничено `login.ftl`, клиентом `imbc-bff` и маршрутами авторизации/проверки пароля; исходный `loginAction`, OIDC и PKCE остаются прежними. Страницы восстановления, одноразовых действий и административного клиента не затрагиваются. Обновление или открытие скопированного `/login` начинает новый вход на стартовую страницу роли; текущая отправка формы сохраняет прежний `returnTo`.

Проверены сборка темы и её JAR на сервере. В браузере пройдены `/login`, неверные реквизиты, обновление до и после ошибки без повторной отправки POST, переключение ru/kk, регистрация и переходы назад/вперёд, открытие восстановления и возврат ко входу. Адрес формы остаётся `/login`, ошибок консоли нет; исходный native POST и параметры действия сохранены. Отдельный HTTP smoke тестового администратора прошёл пароль → `000000` → `/account` → выход, включая лимиты OTP и запрет каталога. Он использовал собственную cookie jar и не отправлял внешних писем.

## Фиксированный OTP для всех демо-ролей

По запросу владельца код `000000` включён также для шести seed-аккаунтов: expert, admin, director, operator, spectator и manufacturer из списка README. В `DEV_FIXED_OTP_ACCOUNTS` записаны шесть точных пар UUID и ожидаемой роли; отдельный `test-admin@imbc.local` сохранён через совместимую настройку `DEV_FIXED_OTP_USER_ID`. Пароли не менялись. Код выдаётся и проверяется по прежним правилам срока действия, попыток и одноразового использования, без отправки письма.

Прошли **83 теста API**, включая **28 интеграционных на отдельной PostgreSQL 18**, проверка типов и production-сборка API. Проверены ошибочные/неоднозначные списки, запрет включения в production, все шесть ролей, повторное создание аккаунта с тем же email и другим UUID, отзыв выданного фиксированного кода после удаления разрешения или изменения роли. Compose корректно передаёт JSON-список API и worker.

На действующем API проверено: из восьми аккаунтов ровно семь используют фиксированный код, один остаётся на почтовом OTP; несовпадений с заданными UUID/ролями нет. Отдельные HTTP-сеансы всех семи демо-аккаунтов прошли реальный пароль → `000000` → разрешённую стартовую страницу → выход. Для каждого проверены обязательная выдача кода, неверный код, повторное использование, пауза повторного запроса и права каталога. Новых писем этим аккаунтам в Mailpit нет. Личный аккаунт владельца не использовался. Временные PostgreSQL и SSH-туннель для автоматических тестов удалены; обновлены только API/worker и список OTP в серверной конфигурации.
