## Proposed API and routes

| Surface | Browser route | BFF operation / strict input |
|---|---|---|
| Full survey records | `/imbc/profiles/:profileId/site-surveys` | GET `/api/v1/profiles/:id/site-surveys`; expert/director `imbc_records.read` |
| Add record | Same page, new record dialog | POST same collection; `SiteSurveyCreate` plus mandatory UUID `Idempotency-Key`; expert `imbc_records.edit` |
| Edit record | Same page, selected record dialog | PUT `.../:recordId`; `SiteSurveyUpdate` with exact `expectedUpdatedAt` UTC6 |
| Fresh exact record | Editor's explicit CAS reload | GET `.../:recordId`; `SiteSurveyRecordView`, independent of page/order |
| Read full history | Selected record history dialog | GET `.../:recordId/history?beforeId=...&limit=25`; scoped exact record history |
| Upload new signed report | Expert editor only | POST `.../files`, multipart `file`; 202 `ProfileUpload` pending/version1 |
| Poll one candidate | Expert editor only | GET `.../files/:fileId/state`; scoped scan metadata; stop at terminal state |
| SME survey requests | `/imbc/site-survey-requests` | GET `/api/v1/site-survey-requests` with final paging/filter contract |
| Manufacturer request | Own verified profile card | GET/POST `/api/v1/profiles/:id/site-survey-requests`, strict `{}` plus mandatory UUID `Idempotency-Key`; own verified manufacturer only |
| Selected company evidence | Existing company page | GET `/api/v1/catalog/companies/:profileId`, `siteSurvey:SiteSurveyCurrentReport|null`; only selected exact dates/report metadata, no whole-record fetch |
| Download exact evidence | Plain same-origin anchor | `/api/v1/files/:fileId/content?version=CAPTURED_NUMBER`; no UUID version query or latest fallback |

The accepted API/read contract includes `SiteSurveyRecordView` (record plus exact `report:ProfileFile|null` and nullable `recordedByName`), `SiteSurveyListRead` (scoped organization name/profile state/tier/summary, `canEdit`, paged records), `SiteSurveyHistory` (full before/after views with own exact report metadata and next cursor), `SiteSurveyRequestRead/List` and `SiteSurveyCurrentReport` (dates plus selected current PASSED report). Company evidence omits result/comment/source/actor/history. Actual company visibility policy action is `catalog.search`; no invented `catalog.company.read` action is added. One manufacturer transport intent can retry idempotently while a later deliberate request remains possible. No status workflow, product, email or invented request-to-record conversion is introduced.

## Full record page

Expert and director see all survey records for the selected existing manufacturer, including no/expired/unsigned migration records. A clear summary reports the backend's current mark/tier and selected visit date. It does not recompute selection from one page of records or infer eligibility from the newest row. The no-expiry state is explicit. Unknown migrated dates/report evidence show reconciliation labels, never the profile creation date or a later uploaded report.

Each record shows visit start/end, result, expiry, complete comment, source, recorder label, recording/update times and captured signed report. Source/recorder/recording timestamp are readonly server facts. Expert gets separate Add/Edit controls. Director mounts only read/history/download components and no uploader/mutation hook. Manufacturer/admin/operator/observer are rejected before full-record queries mount. A typed role policy hint never substitutes for persisted backend checks.

New expert records require actual visit start, yes/no result and a clean signed-report candidate. End/expiry/comment remain nullable; start/end order follows the schema. No guessed one-year or two-year expiry default. Historical dates are accepted as actual values. Editing uses the exact server token, preserves source/recorder/recordedAt and permits known canonical migration rows without a report. Rows marked `needsReconciliation` remain readonly until explicit Stage 8 reconciliation: no generic Edit, guessed source/date, raw-ID-to-latest lookup or clearing original legacy evidence. No delete button or reset-state mutation is added.

## Editor, concurrency and files

Use existing Base UI dialog/field/input/select/textarea/card primitives; official shadcn registry and examples were inspected before new components. Preserve the local `base-nova` implementation; do not import registry Radix examples or overwrite primitives. Dialog uses `grid-cols-[minmax(0,1fr)]`, `min-w-0`, vertical scrolling and wrapping labels/actions at 390 px. Keyboard close returns focus; dirty close/navigation/unload uses the existing unsaved-intent dialog.

A draft and its acknowledged baseline are separate. Save uses the original exact UTC6 `expectedUpdatedAt`; stale 409 keeps dates/result/comment/report candidate, disables resubmission and offers explicit Reload. Reload updates only the fresh comparison/token, shows the current stored record, and keeps the user's draft until Save/Discard. Transport failure retries are controlled; no false saved badge. Actor/record change, unmount or late acknowledgement cannot overwrite another record's local intent.

Survey creation has the coordinator-approved mandatory UUID `Idempotency-Key` with a full parsed-body fingerprint and original audited create receipt. The editor captures one immutable parsed request and key on first Save. Unknown-response retry retains that exact body/key, with fields locked; a later record edit or upload cannot rewrite the original replay receipt/pin. An intentional new record starts a separate dialog/key. This backend seam is not implemented/accepted merely because the client is drafted; actual PG/API and browser replay proof is required before survey acceptance.

`SurveyReport` is a new pure presenter of exact `ProfileFile` metadata. It mounts no query, mutation or own-profile polling hook. Download requires PASSED, known version ID, positive numeric version number and `canDownload=true`. Missing/unsigned/rejected/pending evidence is distinct; original name, size, uploaded date and safe rejection reason are visible. History passes its own pinned metadata, so a current replacement never rewrites the historical file link.

`SurveyReportUpload` is expert-only and uses the final survey-owned upload/poll paths. POST returns 202 `ProfileUpload` with a new object, pending version 1 and no download permission. GET state returns `ProfileUploadState`; a PASSED exact candidate can be saved even while `canDownload=false`, because content permission follows record capture. The pure presenter continues to hide the download until the captured record DTO grants it. No old-object overwrite endpoint is used. File type/25MB/structure/quarantine/storage errors are translated separately. Polling verifies the candidate file ID; a read error stops automatic polling and keeps the candidate for explicit retry. The existing DD uploader and manufacturer attachments are purpose/path-specific and remain untouched.

Accepted responses: POST 201 and PUT 200 return `SiteSurveyRecordView`; exact-detail GET returns the same view. Actual safe problems use the final inventory below, including separate required/unavailable-report and Verified-request-state errors. No temporary survey workflow aliases are used. After terminal authority refusal, all record writes require a fresh list with `canEdit=true` plus exact-detail reread; a read-only detail response alone does not prove edit permission.

## Requests and selected company projection

The manufacturer's own request card is enabled only after a fresh own verified profile read. When mounted on the profile page, it reuses that authenticated response to avoid a duplicate startup fetch; its separate actor-scoped query remains available for explicit fresh recovery. A newer parent status downgrade disables the card and suspends its request reads even if its earlier query cache said Verified. Opening a confirmation creates one in-memory intent UUID; retry after an unknown response retains that UUID. Successful acknowledgement renders the actual request time/list. A later explicit New request generates a new intent; no duplicate click while pending, no product picker, upload, survey record or email. A key conflict requires an explicit new intent after fresh scope validation; a current Verified-state refusal refreshes and disables the action safely. Own request history is paged. No browser storage holds request/profile data.

SME's request list shows safe scoped manufacturer name, actual requested time and a link to that manufacturer's full survey page. No invented accepted/completed request workflow. Requests are not automatically dismissed when a record is added unless the final specification/API explicitly defines that behavior. Director access to the request list follows the final persisted policy, not its permission to read survey records.

Operator/observer company cards use only the selected current survey evidence returned by the authorized company projection. They show report/dates/expiry and the existing tier/mark. They mount no full-record/history/source/actor/result/comment query or mutation control. The file route independently rechecks current visibility, current eligibility and exact pin on each click; UI does not preserve an ineligible old download as current content. Company-page PDF parity is a separate existing export integration gate.
