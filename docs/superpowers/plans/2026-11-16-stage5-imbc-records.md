## File and publication invariants

Use purpose agar_cdp_report + ClassC + manufacturer owner org; capture latest PASSED version only for a changed file intent under sorted object/version locks. Unchanged object retains its exact previous pin even if a newer global candidate is pending. Current/history pins are normalized FKs, not retained only in JSON. ReadRule grants actual active IMBC SME/director with fresh ClassC all policy only saved current/history PASSED pins; manufacturer/operator/observer/admin/unbound uploader get no bytes. No automatic expiry is defined for AGAR/CDP reports.

Tier3 predicate: qualifying enum status + stable identity in current coherent seven-revision Verified projection. Report may be absent; a file alone, visit,100% execution,paused/discontinued or company-level legacy flag never qualifies. Editing status and rebuilding catalog_tier3_product are one profile-locked transaction. No profile tier3 enum or site-survey generation/email changes. Pending product COW remains invisible; after verified publication, membership is recomputed from exact new products revision. A removed product stays in internal history but leaves public tier3 membership. Material product STR applicability validation is Stage9's mapping rule; do not silently add an unprovided AGAR auto-revocation rule to stable identity's status.

Add a pure helper `qualifiesTier3(status)` and shared `rebuildTier3Products(tx,scope,exactVerifiedRevisionMap)` called by accepted review/DD projection writers and AGAR status mutation. Preserve Survey29/NOT11 generation semantics and existing visibility. Public metadata must revalidate current graph/policy rather than trust a stale cached list. Search/dashboard continue distinct manufacturer tier1/2 counts; don't create product tier3 manufacturer counts from summing products. Stage6 exports/pull share the same public allowlist and exclude ClassC reports/comments.
