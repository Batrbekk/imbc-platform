# Durable account NDA evidence — expand slice

Sources: [v1.4 FC-02/03](../../analyst/2026-11-13/specification-v1.4.md), [DBML account_nda_acceptance / nda_acceptance lines 1718–1746](../../analyst/2026-11-13/imbc-platform.dbml). Accepted initial registration records the original tick before password/profile creation. One account/version has one immutable acceptedAt/IP; retries preserve its UUID and facts. A later version appends evidence. Consent never derives from profile creation, password events, or a guessed current manufacturer.

Migration 0022 keeps the old account triplets and profile accepted_at/ip columns for R1. Exact pending triplets backfill first. A legacy profile acceptance supplies original time/IP, but its actor is linked only when successful nda.accepted audit entries name one non-null account, the exact acceptance UUID and the same organisation. Conflicting canonical facts, absent/ambiguous/foreign actors remain an explicit nullable bridge. No consent is fabricated. Organisation is deterministically derived from the existing profile FK.

New application writes require canonical account evidence. Profile creation and an already existing migrated/Verified profile link every durable account version in the same transaction. New direct links have account/source/profile/organisation/version composite scopes. R1 INSERT can still attach its exact matching pending-account triplet; an unsupported legacy writer keeps an explicit unresolved row. All evidence/link tables reject UPDATE/DELETE/TRUNCATE, with application privileges revoked as well.

An unresolved old profile/version already occupies the R1 unique index. A lawful canonical tick cannot replace that old row. `nda_acceptance_bridge` therefore appends a scoped source binding only for that unresolved row. It neither changes the old UUID/time/IP nor claims that a new tick was an old tick. Canonical reads always join account_nda_acceptance for original facts, through direct or sidecar linkage. A source cannot be used in both locations. Profile-parent locks and fresh subsequent reads serialize direct/bridge/replay writes; consent rows are never locked FOR UPDATE.

`nda_evidence_migration_report` is read-only and counts canonical account rows, direct links, raw unresolved legacy rows, bridge-resolved rows and effectively unresolved rows. A bridge resolves present access evidence while retaining the raw historical ambiguity. This is an explicit expand adapter, not a claim that the final DBML contract is fully retired. A later R1 contract migration must fold the adapter while preserving old facts/IDs; it must not quietly invent the missing original actor.

GET/POST `/api/v1/nda/current` requires a persisted active manufacturer with own account/organisation scope and profile.read. A profile is optional. POST accepts only `{versionNumber, accepted:true}`, reads/locks the current nonempty NDA, rejects a changed displayed version, and records canonical evidence, every profile link and audit atomically. Replays do not change time/IP or audit another acceptance. Public registration duplicates and invitation resend behavior stay unchanged. This slice adds no forecast or NDA management UI and no legal text.

Remaining separate behavior: MAN-02 permits a same-BIN + same-email registration retry while initial password setup is still pending. The existing controller still rejects duplicate BIN; testing the separate invitation resend endpoint does not fulfill MAN-02. That retry classifier and behavior are the next bounded change, using the durable evidence from this slice.

Required checks: populated before/after migration, source/time conflicts and ambiguity, signup before profile, later version before/after password, existing-profile linkage without reset, direct and bridge concurrent replays, same-source exclusion after a lock wait, scoped foreign inputs, active-role rechecks, HTTP CSRF, immutable application role, R1 exact INSERT/read roundtrip and transaction rollback.
