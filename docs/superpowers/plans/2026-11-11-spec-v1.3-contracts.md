# Контракты и код под спецификацию v1.3 — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** привести `packages/contracts`, API, web, seed, realm Keycloak и БД к спецификации v1.3: `observer` вместо `spectator`, `unresponsive` вместо `inactive` (виден, сортируется ниже), тир 1/2 в фильтре, результатах и на дашборде, матрица прав по разделу 4.

**Architecture:** перечисления меняются в `@imbc/contracts`, откуда их берут Drizzle-схема, API и web. База переходит по схеме expand → migrate → contract: SQL-миграция только добавляет значения enum, перенос данных идёт отдельной транзакцией после неё, удаление старых значений — следующим релизом. Тир — вычисляемая колонка проекции `catalog_visible`, поэтому каталог и дашборд по-прежнему читают только проекцию.

**Tech Stack:** TypeScript, zod 4, NestJS 12, Drizzle ORM 0.45 / drizzle-kit 0.31, PostgreSQL 18, Next.js 16 + nuqs + next-intl, vitest 5, node:test, Python 3 (sync-realm).

**Spec:** `docs/analyst/2026-11-11/specification-v1.3.md` — разделы 3.1, 4, 5.5, 6.10, 7.1, 7.5; `docs/analyst/2026-11-11/imbc-platform.dbml` (`catalog_profile`, `profile_tier`, `update_freshness`); `docs/handoff/2026-11-11-context.md` §5, §6, §8.

**Редакция 11.11.2026 (после решений владельца).** Web переносится с Next.js на React + Vite SPA отдельным планом `docs/superpowers/plans/2026-11-11-web-vite-spa.md` в отдельной рабочей копии. Поэтому правки `apps/web` из задач 4 и 5 собраны в задаче 9 и выполняются в новом web после слияния. Добавлены задачи 7 (стартовая страница, OPR-31), 8 (карта требований и скрипт сверки) и 9 (интерфейс). Порядок выполнения: 1, 2, 3, 4, 5, 7, 8 → слияние плана web → 9 → 6.

1. `pnpm --filter @imbc/contracts build && pnpm --filter @imbc/api exec drizzle-kit generate --name=spec_v13_expand` — нужен снимок `meta/0003_snapshot.json` с новыми значениями. Режим `--custom` не подходит: он копирует предыдущий снимок.

```sql
-- Спецификация v1.3, шаг expand (NFR-06). Прежние значения 'spectator' и 'inactive' остаются
-- в типах до миграции contract следующего релиза. Новые значения нельзя использовать в этой
-- транзакции: данные переносит backfillSpecV13() (src/database/backfill.ts) после фиксации.
ALTER TYPE "public"."organization_type" ADD VALUE IF NOT EXISTS 'observer' BEFORE 'imbc';--> statement-breakpoint
ALTER TYPE "public"."role" ADD VALUE IF NOT EXISTS 'observer';--> statement-breakpoint
ALTER TYPE "public"."update_status" ADD VALUE IF NOT EXISTS 'unresponsive';
```

Если `drizzle-kit generate` задаст интерактивный вопрос — прервать, выполнить с `--custom` и привести снимок вручную (три списка значений enum).

```sql

UPDATE user_accounts SET role = 'observer' WHERE role::text = 'spectator';
UPDATE manufacturer_profiles SET update_status = 'unresponsive' WHERE update_status::text = 'inactive';
UPDATE catalog_visible SET update_status = 'unresponsive' WHERE update_status::text = 'inactive';
```
