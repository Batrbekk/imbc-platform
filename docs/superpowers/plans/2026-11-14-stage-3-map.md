## Три части

Семь разделов: основные сведения, контакты, персонал, продукты, производство, сертификаты и документы. Источниковые юридические сведения и учредители находятся в основных сведениях только для чтения. Самостоятельных разделов акционеров или юридических/e-Ondiris данных нет. Производство необязательно; общий процент — среднее шести остальных разделов.

| Часть | Видимый результат | Поставки | Зависимость |
|---|---|---|---|
| **3а** основа | Обзор семи разделов; сохранение основных сведений, производственных площадок и контактов; понятные отказы encrypted/attachment документов; подготовка файловой основы | R1 — contract этапа 2 `0011`; R2 — задачи 2–12 и `0012`–`0015` | этап 2; выкат R2 после проверки R1 |
| **3б** секции с файлами | Персонал, продукты, производство, общие сертификаты и документы; одна выписка к списку продуктов; полнота до 100% | один выкат, без contract | 3а R2 |
| **3в** отправка и состояния | Подтверждение достоверности, отправка, блокировка/разблокировка, возврат, явное редактирование Verified и отправленные изменения; тестовые решения SME | выкат функций; отдельно contract этапа 3 | 3б |

Локальное выполнение задач не означает выката или приёмки на Azure. Каждая поставка проверяется отдельно; deploy выполняется по команде владельца.

## Часть 3а — основа

**Цель.** Остатки этапа 2 до открытия producer uploads; семь разделов на текущем DBML; основные сведения и контакты без загрузки файлов в формах.

**Требования.** GEN-11; MAN-04, MAN-09–11, MAN-13–15, MAN-21–22; MAN-40–41, MAN-43, MAN-45–46 частично; DATA-01; остатки GEN-09, DATA-04, DATA-06–07, NFR-06, NOT-18.

**Задачи 1–4** — contract этапа 2, DOCX/XLSX, PDF/rejection reason, upload concurrency. Любой PDF с /Encrypt отвергается; прежнее исключение для permissions-only PDF не применяется. Обязателен корпус реальных файлов и ревью ограничений парсера.

**Задачи 5–12** — по [подробному плану v1.4](2026-11-16-stage-3a-spec-v1.4.md):

5. Schema expand, семь sections, stable site/product/certificate identities, актуальные дочерние таблицы, tenant FK и immutable guards. Переименование `manufacturer_profiles` в `manufacturer_profile` сохраняет простое совместимое представление; обязательны точные R1 SQL и проверка старого приложения на новой схеме.
6. Общий core, copy-on-write всех детей, editVersion/conflict, доступность/lock, полная история before/after, полнота шести секций. Отметки подтверждения Adata отсутствуют.
7. File access по owner revision; выписка products_section, множественные org charts, equipment photo, shared certificate. Используемые dictionary values защищены FK.
8. Main API: readonly legal/Adata OKED/founders; editable website/phone/email и ordered sites. Missing source не мешает полноте; site identity сохраняется при исправлении.
9. Contacts API: минимум три, один focal point, международные номера/нормализованные дубли; без верхнего бизнес-лимита и shareholder API.
10. Обзор семи разделов и main/site form; readonly Verified с явным Edit; источник внутри main, без отдельной legal tab.
11. Contacts form, немедленная ошибка второго focal point, partial save, ошибки/dirty/conflict, en/ru/kk.
12. Документы, проверки миграций и полного корпуса, независимое итоговое ревью, локальная приёмка и отдельная стендовая проверка после разрешённого выката.

При полных main и contacts и остальных нулевых обязательных разделах профиль — 33⅓% (при отображении целым вниз 33%), а не прежние 42%. Отправки на этом срезе нет.

## Часть 3б — секции с файлами

**Цель.** Открыть загрузки и пять остальных форм; профиль может дойти до 100% без требований, удалённых в v1.4.

**Требования.** MAN-17–20, MAN-23–24, MAN-26–39; MAN-40–41, MAN-46; MAN-12 (необязательная выписка); GEN-09, DATA-05–07.

Предварительные задачи, окончательная разбивка — после приёмки 3а:

1. Producer upload/replace с tenant/purpose, scan status/rejection, историей версий и очисткой непривязанных файлов. Зафиксировать срок очистки; frozen files не становятся latest автоматически.
2. Personnel API: managers/engineers/production workers, computed total; nonresident_count как подмножество всего штата; минимум один org chart, можно несколько; optional CV и sample.
3. Shared certificates API: stable certificate_identity; группы company/product/other; номер, issuer text, дата и optional expiry; company ISO 9001/14001/45001 — held или explicit not_held. Декларация исключается из полноты и не становится verified held certificate. Нет новых типов CT-KZ/industrial certificate и отдельной conformity file.
4. Products API: stable product identities, names en/ru у manual line; descriptive type → parent group; TN VED text/ref, KPVED rows; numeric annual capacity + unit; выбор существующего site; M:N ссылки на held product certificates, которые загружаются один раз. Одна optional extract в products_section. Нет manual DVC/localization fields: nonregistry DVC всегда 0.
5. Production API: optional area/processes/workshops/utilisation/equipment и связи equipment → stable product; у каждой полной equipment row своё photo. Optional section не снижает общий процент.
6. Documents API: registration certificate, charter, admin-required additional types, custom name + file. Нет licences/licence-not-required declaration или неподтверждённой матрицы по legal form.
7. Web file slot, personnel, sample, multiple charts/CV и extract в Products.
8. Web products/production: повторное использование product certificate, inline создание сертификата, без inline site creation. Изменение shared certificate не раскрывает pending replacement оператору.
9. Web certificates/documents: группы, absence declaration, статусы и история, completeness errors.
10. Документы и приёмка: полный профиль 100%; реальные 20–25 MB files через Caddy/ClamAV/storage; access refusals всех ролей.

**Граница источника:** pulled product facts производитель не правит/не удаляет; local site/certificate associations editable. Дубликат — exact name + TN VED, не code alone. Привязка к e-Ondiris immutable snapshot; заменяя manual duplicate, source sync сохраняет stable identity и local associations. Подготовка source-refresh — 4б, без исключения из frozen guard.

## Часть 3в — отправка и состояния

**Цель.** Отправка и решения по текущему профилю, без передачи непроверенных значений оператору. До этапа 5 решения SME подставляются test-only command.

**Требования.** MAN-41–46; ADM-09; DATA-01; GEN-11; основы REV-01–04 для review cycle.

1. Review assignment/decision и снимок обязательных типов submission_requirement; сохранение file-version snapshot при отправке.
2. Отправка: 100%, явная accuracy confirmation, freeze working revisions, pending pointers, Submitted; received_at новой проверки. Недостающие поля/файлы объясняются со ссылками.
3. Unlock: Draft или Verified с сохранением предыдущих проверенных данных; закрывает текущий assignment; нетронутые решения сохраняются; новая отправка прежнему SME и с новой received_at.
4. Return: отклонённые sections/files с комментариями; verified untouched остаётся verified. ISO not_held — решение по декларации, не по отсутствующему файлу.
5. Verified editing: сначала просмотр, затем явный Edit; save создаёт working revision. Только Send changes for review создаёт pending_revision_id и очередь SME; сохранение working Verified draft не ставит legacy has_pending_changes. Pending values не меняют проекцию; профиль остаётся Verified.
6. Test-only review command (SEED_DEMO=true, .local actor, аудит, без HTTP route) до SME workflow этапа 5.
7. Web dialogs/states/comments/missing links, объяснение отдельной отправки изменений.
8. Повторяемый E2E draft → submit → return → resubmit → verified → edit → send changes; tenant/role/file refusals, конкурентные замены/отправки; визуальная проверка 1280/390 px.
9. Contract этапа 3 отдельным релизом: удалить только проверенный неиспользуемый скелет и совместимое представление manufacturer_profiles после retirement R1; снять переходные profile columns по отдельной проверке. Перестроить старые worker queries перед drop; проверить backup/restore и границу rollback.
10. Документы, итоговая приёмка этапа 3; письма/SME UI остаются в этапе 5.

## Границы других этапов

- **4б:** readonly Adata legal/full OKED/founders и audited source history; producer contact/site corrections не стираются; e-Ondiris immutable source records и product refresh с local links. Нет per-field producer confirmation.
- **5:** SME review queue только текущих отправок, ISO absence/applicability decisions, due diligence full before/after audit, normalized IMBC engagement/product context; tiers и проекция.
- **6:** разрешённые operator/observer files и verified profile/site/certificate view; мультиплощадки дают несколько region facets, distinct manufacturer один раз. Director dashboard только visible verified, company/catalog — все profiles.
- **6б:** самостоятельный LPS register/table/dashboard, SME CRUD и operator/director readonly, без роли производителя/наблюдателя/администратора. Этот модуль не раздел профиля и не gate через manufacturer verification/NDA.
- **7:** reminder generations certificate_expiry_schedule; update status/section confirmations; нет возврата отменённого подтверждения юридических полей Adata.
- **8/9:** current DBML import/export mappings, separate LPS migration, horizon 2031 metadata и approved STR product mapping.
